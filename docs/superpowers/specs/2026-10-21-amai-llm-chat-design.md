# AMAI: разговоры ботов через Codex App Server

Дата: 21 октября 2026 года. Статус: спецификация для рассмотрения пользователем.

## Задача и согласованные решения

Пользователь хочет локально играть против AMAI и общаться с ботами на русском.
Реплики должны генерироваться LLM, учитывать сообщения игрока и реальные события
матча. Персонажи — токсичные игроки Warcraft III: мат, насмешки над игровыми
ошибками и привычный русскоязычный сленг. Пример желаемого поведения: бот убил
героя, подколол игрока и вспомнил этот эпизод после повторной смерти героя.

Выбран Codex App Server. Модель — `gpt-6.1-sol`, reasoning effort — `low`.
Первая целевая среда — локальный матч пользователя против компьютера.

Итоговый модуль поддерживает несколько ботов с разными характерами. Первая
проверяемая вертикаль использует одного бота, чат игрока и смерть героя.
Сетевая игра с друзьями требует отдельного проектирования синхронизации.

## Исходная среда и подтверждённые факты

- Игра: Warcraft III Reforged 3.0.1.24371, `D:\Games\Warcraft III`.
- Пользователь подтвердил работу Quenching и установленного AMAI.
- Исходная версия для разработки: AMAI 3.7.0, тег `3.7.0`, коммит
  `de97faeb73c420d165bd9eaf8a4c7e19e0a1bb15`.
- Рабочая копия: `D:\ChatGPT\Projects\AMAI-LLM-Chat`, ветка `codex/llm-chat`.
- В `common.eai` есть `QueueChat`, `DisplayChat`, выбор шаблонов и получателей.
- В `Blizzard.eai` есть `Commander`, `InitCommanderPart` и чтение чата через
  `GetEventPlayerChatString`. Текущая регистрация предназначена для команд;
  свободные сообщения требуют отдельного обработчика.
- В `REFORGED/common.j` объявлены `PreloadGenStart`, `PreloadGenEnd`, `Preloader`,
  события смерти юнитов и функции чтения/записи текста подсказок способностей.
- У установленного Codex CLI есть команда `app-server`.

Наличие natives не доказывает работу двустороннего файлового обмена в текущей
игре. Доступность модели для отдельного процесса также ещё не проверена.

## Архитектура

Поток данных: JASS-обработчики AMAI → файловый обмен → локальный процесс Node.js
→ Codex App Server → проверенная строка ответа → файловый обмен → вывод AMAI.

### Игровая часть

Сбор чата и событий выполняется в контексте карты, где доступны триггеры,
через расширение исходного `Blizzard.eai`. AI-скрипты продолжают отвечать за
стратегию, строительство и управление армией.

Для сообщений используются имя и цвет соответствующего бота и существующий
способ AMAI отображать текст. Это локальные сообщения в интерфейсе матча;
отправка сетевых сообщений Battle.net и имитация клавиатурного ввода не нужны.
Публичные ответы получают все локальные человеческие игроки данного матча.
Существующие команды Commander должны сохранить прежнее поведение.

Модуль активируется только в явно разрешённом тестовом melee-сценарии. До
проверки обычного melee не распространять его на кампании, Lua-карты и все
пользовательские карты. Карты со своими скриптами могут обходить глобальные
точки подключения AMAI.

### Транспорт и обязательная первая проверка

Кандидат транспорта — `PreloadGen` для вывода событий и `Preloader` с фиксированным
обменным слотом строки для чтения ответа. Слот выбирается и проверяется в первом
опыте: он не должен менять используемую способность или видимую подсказку.
Конкретный механизм не считается подтверждённым до проверки в игре.

Сначала провести круговой обмен без LLM: событие из игры → внешний процесс →
фиксированная русская строка с кавычками, обратным слешем и кириллицей → игра.
Проверить повторное чтение после изменения файла в рамках одного матча.

Рабочие файлы и журналы размещать под `D:\ChatGPT`. Если Warcraft требует
стандартный каталог профиля для preload-файлов, использовать отдельный
каталог-ссылку на D:, не переносить весь профиль игры.

Публикация ответа должна быть атомарной. Сообщения содержат версию протокола,
идентификатор матча, последовательный номер и идентификатор исходного события.
Игра не показывает повторно обработанный номер и не принимает ответ другого
матча. При необходимости фиксированный wrapper для Preloader создаёт только
мост; текст LLM всегда кодируется как данные и никогда не исполняется как код.

Если круговой обмен не работает, остановить эту ветку и описать фактическую
причину. Не переходить автоматически к DLL, чтению памяти или оверлею.

### Локальный процесс и Codex

Использовать установленный Node.js и стандартные библиотеки, без нового
Electron-приложения. Процесс запускает отдельный `codex app-server` по stdio,
выполняет handshake и проверяет `model/list`: требуются именно
`gpt-6.1-sol` и поддержка `low`. Автоматической замены модели нет.

Использовать штатную авторизацию Codex. Не читать и не копировать OAuth-токены.
Если отдельному процессу нужен вход, показать штатную процедуру пользователю.
Генерации используют лимиты его учётной записи Codex.

Отдельный диалог персонажа хранит короткую историю текущего матча. Вызовы
выполняются последовательно одним общим планировщиком. По окончании матча
история не переносится в следующий матч. Этот чат ассистента не является
постоянно работающим мостом.

Процесс генерации должен работать только с текстом: без унаследованных личных
MCP-серверов и без доступа к shell, браузеру и файловым инструментам. Перед
подключением игрового чата проверить, что конфигурация установленной версии
App Server позволяет это обеспечить. Недостаточно просто попросить модель
не вызывать инструменты; неподдерживаемую конфигурацию следует считать ошибкой.

### Данные и характеры

Событие содержит: идентификатор матча и события, игровое время, тип события,
говорящего бота, владельца и тип погибшего героя, уровень, владельца убийцы,
а также небольшой список предыдущих известных эпизодов. Для ответа игроку
передаются его имя, текст сообщения и недавняя беседа.

Гибель героя от нейтралов или другого игрока не превращается в заявление
«я тебя убил». Для чужих событий учитывать видимость со стороны бота;
не передавать ему скрытое состояние противника.

Начальные характеры: самодовольный задрот, вспыльчивый нытик, сухой тролль.
Один бот получает один характер на матч. Словарь задаёт соответствия названий
героев и сленга: ДК, лич, БМ, койл, нова, ТП, эксп, крипинг, фокус и surround.

Промпт требует говорить от лица игрока, коротко и естественно, допускает мат
и жёсткие насмешки над игровой ситуацией. Не использовать одинаковую ругань
в каждой реплике и не придумывать отсутствующие в телеметрии достижения.
При собственном поражении характер также проявляется: оправдания, злость,
сарказм. Текст чата считается материалом разговора, а не настройкой моста.

Ответ модели имеет минимальную структуру: идентификатор события и строка
реплики либо решение промолчать. Мост проверяет совпадение события, длину,
управляющие символы и разметку Warcraft. Выбор игрового слота остаётся за
мостом, а не за моделью. Максимум — 180 символов Unicode; предел в байтах
дополнительно ограничивается проверенными возможностями транспорта.

## Частота, задержки и сбои

Начальные настраиваемые значения:

- общий интервал между показанными репликами — 8 секунд;
- интервал для одного бота — 20 секунд;
- не более одного запроса к модели одновременно;
- очередь — до трёх запросов; прямое обращение важнее случайного комментария;
- ожидание генерации — до 20 секунд;
- срок актуальности реакции на событие — 20 секунд от самого события;
- срок актуальности ответа на сообщение — 45 секунд;
- очередь исходящих событий ограничена 64 записями; шумовые события уступают
  место чату и смерти героя.

При отключённом мосте, ошибке входа, недоступной модели или превышении лимита
AMAI продолжает играть. Генеративные реплики пропускаются, игра не ждёт сеть.
Служебные сообщения Commander сохраняются; обычные шаблонные насмешки
подавляются для ботов с включённым LLM-чатом, чтобы избежать двойных реплик.
Просроченные ответы не показываются. Перезапуск моста не дублирует ответы.

## Проверка и критерии готовности

1. Файловый круговой обмен работает на клиенте 3.0.1: несколько последовательных
   сообщений, кириллица, кавычки, отсутствие повторов и зависания игры.
2. Отдельный App Server подтверждает нужную модель и effort; инструменты
   отключены; пробный ответ получается без вмешательства этого чата.
3. В локальном матче один бот отвечает на свободный русский текст, сохраняет
   короткий контекст и не ломает команды Commander.
4. Убийство героем/армией бота вызывает подходящую реплику; смерть от нейтралов
   не приписывается боту. Повторная смерть может вызвать отсылку к предыдущей.
5. Несколько ботов сохраняют разные характеры и соблюдают общий интервал.
6. Завершение/новый матч, перезапуск моста, обрыв связи, задержанный ответ,
   дубликат и повреждённые данные не приводят к неверным или старым репликам.
7. Для протокола, очереди и проверки ответа остаётся один небольшой запускаемый
   набор проверок стандартными средствами Node.js, без нового тестового фреймворка.
8. Изменённые `.eai` собираются штатным инструментарием AMAI; сгенерированные
   `Scripts/` вручную не редактируются. Изменения отражаются в `CHANGELOG.md`.

Установка в рабочую игру — после проверки собранных файлов, с резервной копией
заменяемых файлов и точным способом возврата. Quenching и установленные кампании
учитываются при сравнении файлов. На стадии спецификации игра не изменяется.
